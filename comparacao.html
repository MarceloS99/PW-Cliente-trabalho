Comparação Técnica de Frameworks CSS

Implementação isolada do mesmo componente turístico (cartão informativo da Ponte D. Luís I) em Bootstrap 5.3.3, Foundation 6.8.1 e W3.CSS 4.15 para avaliação de desempenho, código e acessibilidade.

1. Mesmo Componente Implementado nas Três Frameworks

Cada caixa abaixo renderiza o componente de forma isolada com a respetiva folha de estilos oficial via CDN e a paleta institucional (#1A365D e #975A16).

Bootstrap v5.3.3 14 linhas HTML
Foundation v6.8.1 16 linhas HTML
W3.CSS v4.15 14 linhas HTML

2. Tabela Comparativa de Critérios Técnicos

Medição empírica dos indicadores de desempenho, código, personalização e acessibilidade por defeito.

1. KB Transferidos (CSS minificado / gzip) 232 KB bruto (~31 KB gzip) 154 KB bruto (~21 KB gzip) 23 KB bruto (~5 KB gzip)

6. Ecossistema de Componentes sem JS Extra Completo (Navbar, Accordion, Table, Badges, Alerts) Completo (requer jQuery/plugins adicionais para interatividade) Minimalista (necessita JavaScript manual para acordeões/menus)

3. Método de Medição Utilizado

Para assegurar rigor e reprodutibilidade na comparação entre as três bibliotecas CSS, aplicou-se o seguinte protocolo experimental:

  1. Isolamento de Ambiente: O mesmo componente funcional (cartão de monumento com cabeçalho visual, etiqueta geográfica, título hierárquico, descrição e botão de ação) foi implementado em três documentos HTML independentes embebidos via <iframe srcdoc>, impedindo colisões de seletores globais.
  2. Medição de Rede (KB Transferidos): Utilizou-se o separador Network do Google Chrome DevTools (com cache desativada — Disable cache) para registar o tamanho transferido (gzip) e o tamanho descomprimido (bruto) de cada folha de estilos oficial carregada via CDN.
  3. Contagem de Código: Contabilizaram-se as linhas efetivas de marcação semântica HTML e de regras CSS personalizadas necessárias para aplicar a paleta oficial (#1A365D e #975A16) com idêntico resultado visual.
  4. Auditoria de Acessibilidade e Documentação: Verificou-se o comportamento de foco por teclado (tecla Tab), o rácio de contraste (superior a 5.1:1) e o suporte nativo a atributos WAI-ARIA na documentação oficial de cada projeto.
